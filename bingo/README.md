# 強奪ビンゴ — 運営ツール

リアル交渉ゲーム「強奪ビンゴ」の運営ツール一式。ビルド不要の静的ファイルです。

- **集計ツール**: https://tools.puzzliar.jp/bingo/ （GM用。秘匿台帳・抽選・投票/強奪受付・開票・最終精算）
- **発表画面**: https://tools.puzzliar.jp/bingo/display.html （プロジェクター用。公開情報のみ表示）

ルールエンジンのテストはリポジトリ直下で `npm test`（`test/bingo/`）。

ルールの出典：Google Drive の `強奪ビンゴ_ルールブック_単ページ.pdf`（2026-06）。運用は過去の集計表（`強奪ビンゴ集計表_20190721_第2部.xlsx`）の進行表を参考にしています。

| ツール | ファイル | 用途 |
| --- | --- | --- |
| **集計ツール** | `bingo/index.html` | GM用。秘匿台帳（名前・プレイヤーNo.・口座記号・ビンゴカード）を管理し、抽選 → 投票・強奪受付 → 開票 → 次ターンを処理。IN/OUT・変更・除外カード、最終強奪、最終精算まで対応。 |
| **発表画面** | `bingo/display.html` | プロジェクター用。出玉（X/Y/Z）、開票結果、玉の状況、口座残高の途中発表（口座記号ごと）、IN/OUT発表、タイマー、最終結果の順次発表。 |

## 使い方

1. 集計ツールで参加人数・名前を入力し、プレイヤーNo.と口座記号を割り当て（「No.・口座記号をランダム割当」も可）、配布したビンゴカードの9マスを左上から右へ入力して「ゲーム開始」。
2. 「発表画面を開く」でプロジェクター用の画面を開く。
3. 各ターン：
   1. **抽選**：ビンゴマシーンから出た玉を出た順に X・Y・Z へ入力（前ターンの IN/OUT とマシーン補充はターン開始時に自動反映され、画面に表示されます）。
   2. **投票・強奪受付**（5分）：強奪申請カード、IN/OUT申請カード、変更カード、除外カード（9ターン目以降）を受け付けた順に入力。最後に X/Y/Z の票数と無効票数を入力すると判定プレビューが出ます。
   3. **開票結果**：有効数字、ビンゴ成立（秘匿）、強奪の処理結果（秘匿）を確認して「次のターンへ」。口座の移動があれば発表画面は自動で「口座残高」（途中発表）に切り替わります。
4. 15ターン目の後は「最終強奪の受付」→「最終精算」（各プレイヤーが提出したチップ額を入力）→「最終結果」。発表画面で下位から1人ずつ公開します。

保存・読込・元に戻す・タイマーの操作は制限すごろくと同じです。データは `robberBingo.*` のキーでブラウザに保存され、他のゲームとは干渉しません。

## 実装しているルール

- 初期配布：チップ 1,100,000 L$（プレイヤー所持・終了時に提出）、口座 2,000,000 L$（事務局管理）
- 玉は1〜27。各ターン3つ出し、出た順に X・Y・Z
- 開票：最多票の数字が有効。同率1位なら次点が繰り上がり有効。全て同率なら全て有効。投票数がプレイヤー数の過半数に届かなければ全て無効
- 有効にならなかった出玉はプールへ。ターン開始時にマシーンが空ならプールの玉をマシーンに戻す
- ビンゴは3×3カードのタテ・ヨコ・ナナメ8列。成立した列ごとに通算の列番号（1列目〜8列目）が付く
- 強奪：k列目が成立した**次のターン**に申請した場合のみ有効。対象の口座残高 × 割合（1〜6列目 10〜60%、7列目 80%、8列目 100%、端数切り捨て）。15ターン目の成立分は最終強奪の受付で処理
- IN/OUT申請カード（20,000 L$）：同じ数字への IN と OUT は枚数の多い方が有効、同数は移動なし。次ターンの玉を出す直前に反映。有効になった玉・除外された玉は対象外
- 変更カード（400,000 L$）：カードの1マスを任意の数字に変更（カード内の重複・有効済みの数字は不可）。即時反映
- 除外カード（250,000 L$）：9ターン目以降、有効になっていない玉を1つ完全に除外。即時反映
- 終了時：全8列成立 +1,000,000 L$、1列も成立していない −1,000,000 L$
- 最終所持マネー = 口座残高 + 提出チップ + ボーナス/ペナルティ。最も多いプレイヤーが優勝（同額は同順位）。差し引き（最終 − 3,100,000 L$）が0以上なら「事務局に対する勝利」

特殊カードの代金はチップ（現物）で支払うため、集計ツールでは金額を管理せず効果だけを記録します。

## ルールブックに明記がなく、運営判断として実装した解釈

運用を変える場合は `bingo/js/engine.js` を調整してください。

| 論点 | 実装 |
| --- | --- |
| 過半数の数え方 | X・Y・Z への有効票の合計が「プレイヤー数 ÷ 2 の切り捨て + 1」以上（無効票は数えない） |
| 出玉が2個以下のターン | 出玉が全て同票なら全て有効。それ以外は通常どおり |
| ペナルティの条件 | 「1列以上ビンゴが成立していない」を **1列も成立していない** と解釈（全列成立でなくてもペナルティにはならない） |
| 強奪の処理順 | 開票時に申請順で処理。各申請はその時点の対象の残高に割合を掛ける |
| 自分への強奪 | 不可 |
| 変更カードと成立済みの列 | 一度成立した列は、その後カードを変更しても取り消さない |
| 除外カードの対象 | 今ターンの出玉（X/Y/Z）は対象外 |
| 差し引きの基準額 | 初期配布の合計（チップ 1,100,000 + 口座 2,000,000 = 3,100,000 L$） |

## 公開・非公開

発表画面には `publicView()` が抽出した公開情報だけが送られます。ルールブックの非公開情報である **どの口座記号が誰のものか**、**誰が誰から強奪したか** に加え、各自のビンゴカードと成立列も送りません（最終結果の発表時のみ名前・No.・口座記号を公開）。
